# FreeNovel Validation

## 验证原则

验证保持轻量、贴近改动：

- 后端 bug 或配置改动：运行能覆盖该问题的 Maven 构建、启动检查、接口检查或日志检查。
- 前端 bug 或配置改动：运行能覆盖该问题的 build、lint 或浏览器手动验证。
- Docker/Compose 改动：至少检查 compose 配置能解析；如本地条件允许，再启动验证。

## 书源接入验证（本阶段重点）

- desktop_browser renderer：必须至少验证一个 webView:true 真实书源的搜索、详情、目录、正文链路，正文实际可读。
- cookie 支持：必须验证需 cookie 的书源在持久化 cookie 后正文能取到。
- 渲染结论必须区分 `http`、`desktop_browser`、`needs_app_review`，不能冒充。
- 外部站点失败时，要记录是网络、规则、登录态、验证码、CSR、正文抽取、cookie 失效还是编码问题。
- 不能只看"接口 200"，正文要确认实际可读。

## 通用规则

- 文档整理：核对文档描述是否与当前源码、配置和命令一致（注意 README 引用的 docs/ 路径不存在这一失准）。
- 如果本地数据库、外部服务、登录态或浏览器驱动不可用，明确说明阻塞点，不把未验证路径写成已通过。
- 不要求生成截图、AI logs、专门测试文档或任务记录，除非用户单独要求。
